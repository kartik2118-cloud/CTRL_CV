# Contract: Extension <-> Backend (Active Implementation)

Transport: One WebSocket per active tab capture session (default: `ws://localhost:8000/ws`).
Privacy: Audio leaves the local browser context; the extension must display a visible notice in the popup and provide an ON/OFF toggle switch to terminate transmission and audio capture.

---

## 1. Session Handshake

### Client -> Backend (JSON text frame)
```json
{
  "type": "hello",
  "client_id": "client_abc123",
  "lang": "hi",
  "target_lang": "en"
}
```
- `client_id`: Unique tab/session identifier generated by the client.
- `lang`: Source audio language code (`"hi"`, `"en"`, etc.).
- `target_lang`: Desired subtitle translation language code (`"en"`, etc.).

### Backend -> Client (JSON text frame)
```json
{
  "type": "hello_ack",
  "session_id": "client_abc123",
  "epoch": 0
}
```
- `session_id`: Confirmed session identifier.
- `epoch`: Initial session epoch counter (typically `0`).

---

## 2. Audio Chunk Streaming

Two frames per chunk, transmitted consecutively:

1. **JSON text frame (`chunk_meta`)**:
```json
{
  "type": "chunk_meta",
  "chunk_id": 17,
  "epoch": 3,
  "video_start": 60.0,
  "video_start_time": 60.0,
  "playback_rate": 1.5,
  "sample_rate": 16000,
  "duration": 1.0
}
```
- `chunk_id`: Monotonically increasing chunk identifier within the tab session.
- `epoch`: Current epoch counter.
- `video_start` / `video_start_time`: Video timeline seconds at the first sample of the chunk.
- `playback_rate`: Video playback speed multiplier during audio capture.
- `sample_rate`: Audio sampling rate in Hertz (`16000`).
- `duration`: Audio span duration in seconds (`1.0`).

2. **Binary frame**:
- Raw 16 kHz mono 16-bit signed linear PCM (little-endian byte order).

---

## 3. Subtitle Results

### Backend -> Client (JSON text frame)
```json
{
  "type": "subtitle",
  "chunk_id": 17,
  "epoch": 3,
  "start": 66.0,
  "end": 67.2,
  "lang": "hi",
  "text": "आज हम पनीर टिक्का बनाएंगे",
  "translation": "Today we will make paneer tikka",
  "source": "stt"
}
```
- `start` / `end`: **ABSOLUTE video timeline seconds**, pre-calculated on the backend using the formula:
  $$t_{\text{start}} = \text{video\_start} + \text{offset\_start} \times \text{playback\_rate}$$
- `source`: Identifier string (`"stt"` or `"mock"`).
- What is absent from the current backend payload:
  - `is_final` is omitted (backend produces one final subtitle per segment).
  - `langs` array is omitted (backend sends only single string `lang`).
  - Relative `start_offset` and `end_offset` are omitted (backend sends absolute timestamps directly).

---

## 4. Time Conversion & Double-Conversion Invariant

Because the real backend sends absolute video seconds in `start` and `end`, the extension normalizer back-computes chunk-relative audio offsets using the registered chunk context:
```javascript
start_offset = (start - video_start_time) / playback_rate
end_offset   = (end   - video_start_time) / playback_rate
```
When `SyncEngine` computes `video_start_time + start_offset * playback_rate`, it recovers the backend's exact absolute timestamp. This eliminates double conversion:
- Example: `rate = 1.5`, `video_start = 60.0`, `backend start = 66.0`.
  - Normalizer: `start_offset = (66.0 - 60.0) / 1.5 = 4.0`.
  - Engine: `t_video = 60.0 + 4.0 * 1.5 = 66.0`.
  - Result: `cue.start === 66.0` (not `126.0`).

## 5. Control Messages

### Seek / Discontinuity Control
Client notifies backend on seek, YouTube SPA navigation, or video ad start/end:
```json
{
  "type": "seek",
  "video_time": 45.0,
  "epoch": 4
}
```
Backend response:
```json
{
  "type": "seek_ack",
  "epoch": 4,
  "video_time": 45.0
}
```
Advancing the epoch causes all in-flight or older chunks to be discarded immediately.

### Configuration Update
Client adjusts parameters dynamically:
```json
{
  "type": "config",
  "playback_rate": 1.25,
  "lang": "hi",
  "target_lang": "en"
}
```
Backend response:
```json
{
  "type": "config_ack",
  "playback_rate": 1.25,
  "lang": "hi",
  "target_lang": "en"
}
```

### Disconnect
```json
{
  "type": "bye"
}
```
Server closes connection cleanly with code `1000`.

---

## 6. Fields We Still Need From the Backend

1. **`is_final` (boolean)**:
   - Needed to support streaming partial transcriptions (`is_final: false`) before the finalized sentence (`is_final: true`). Currently absent from backend `SubtitleResult`.
2. **`langs` (array of strings)**:
   - Needed for code-mixed speech representation (e.g. `["hi", "en"]` for Hinglish). Currently absent; backend only provides `lang: string`.
3. **Word-level timestamps / offsets (`start_offset`, `end_offset`)**:
   - Needed for karaoke-style word highlighting and fine-grained latency evaluation. Currently absent from mock and non-diarized providers.

## 7. Superseded (v0.1 Contract Draft)

The following original draft contract is preserved for historical reference:

```markdown
# Contract: Extension <-> Backend (v0.1)

Transport: one WebSocket per tab session. Audio leaves the browser, so the extension must show a notice and an off switch.

## 1. Session start (extension -> backend, JSON text frame)
```json
{"type": "start", "session_id": "abc123", "translate_to": "en", "lang_hint": null, "dual": true}
```
`lang_hint` is null for auto-detect. Backend replies `{"type": "ready"}`.

## 2. Audio chunk (extension -> backend)
Two frames per chunk, in order:

1. JSON text frame (header):
```json
{"type": "chunk", "chunk_id": 17, "epoch": 3, "video_start_time": 60.0, "playback_rate": 1.5, "sample_rate": 16000}
```
2. Binary frame: raw PCM, 16 kHz, mono, 16-bit signed little-endian.

- `video_start_time` = `video.currentTime` (video seconds) at the first sample of the chunk.
- `epoch` is a counter. The extension increments it on every seek, navigation, ad start/end and tab reset.
- Cut chunks at pauses (VAD). Do not cut mid-word. Target 1-4 s per chunk.

## 3. Result (backend -> extension, JSON text frame)
```json
{"type": "result", "chunk_id": 17, "epoch": 3, "is_final": true,
 "start_offset": 0.8, "end_offset": 4.0,
 "lang": "hi", "langs": ["hi"], "text": "आज हम पनीर टिक्का बनाएंगे",
 "translation": "Today we will make paneer tikka"}
```
- Offsets are AUDIO seconds from the start of the chunk. The backend never converts to video time.
- `langs` has two entries for code-mixed speech, for example `["hi", "en"]`.
- `is_final: false` = partial text. The same `chunk_id` may be sent again with improved text (each change is logged as a revision).
- Errors: `{"type": "error", "code": "...", "message": "..."}`.

## 4. Time conversion (extension does this, once)
```
start = video_start_time + start_offset * playback_rate
end   = video_start_time + end_offset   * playback_rate
```
Example: chunk at 60.0 s, word at +4.0 s, rate 1.5 -> 60.0 + 4.0 * 1.5 = 66.0 s.
Use the `playback_rate` echoed in the chunk header that was sent, not the current rate.

## 5. Epoch rule
Any result whose `epoch` differs from the current epoch is DROPPED, never rendered, never logged. This is how stale results after a seek or an ad are removed. The backend echoes `epoch` and `chunk_id` unchanged.

## 6. Cue log (exported by the extension)
One entry per subtitle: `start`, `end`, `lang`, `text`, `translation`, `source` ("stt" or "captions"), `first_shown_at` (video time when final text first appeared in full), `revisions: [{at, text}]`. All times are VIDEO seconds.
```
